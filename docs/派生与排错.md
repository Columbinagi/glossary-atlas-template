## 一、接线点（派生必改 5 处）

### 1. 产物文件名写死在 3 个脚本里

`engineering/拼合.mjs:17`、`engineering/校验.mjs:17`、`engineering/预览服务.mjs:33` 三处硬编码同一个产物路径 `dist/<源项目品牌名>.html`，品牌名与 `content/站点配置.js` 的 `SITE_META.brandName`（模板里现成的那份）同值。

> **这一条不是首跑拦路虎**（2026-10-05 独立黑盒测试实测并修正了本文档此前的说法）：三处硬编码**同值**，产物名与查找路径始终一致，因此不改也能跑绿——实测把 `brandName` 改成别的名字后，拼合与校验仍然 exit 0。它是**命名一致性缺陷**，不是失败点；副作用是品牌名改了以后顶栏简称/页脚不会自动跟着走（见第 4 条）。

建议改成由站点配置推导，以后换主题只改一处：

```js
// 拼合.mjs / 校验.mjs —— 站点配置是普通 var 脚本，不能 import 取导出，直接读文本
const cfgText = fs.readFileSync(path.join(CONTENT_DIR, '站点配置.js'), 'utf8');
const BRAND = cfgText.match(/brandName:\s*'([^']+)'/)[1];
const OUT = path.join(ROOT, 'dist', BRAND + '.html');
```

```js
// 预览服务.mjs:33 —— 纯静态服务器读不了配置，需手动同步成同一个文件名
const HOME_FILES = ['index.html', 'dist/<你的品牌名>.html'];
```

### 2. 校验里的「搜索语料回归」探针写死

`engineering/校验.mjs:301` 的 `const probes = ['永磁', 'ycdj'];`，配合 303–304 行的 `#topic=t5`，断言「中文界面能搜到 ≥ 1 卡，英文界面命中数不少于中文」。换成新主题后这两条必红（实测：新主题 0 卡）。

三种改法：

- **换成你的首条词条**：探针换成它的名字与拼音首字母串，并把两处 `#topic=t5` 换成它所属主题 id。
- **从数据推导**：取 `DEFAULT_TOPIC` 的第一张卡，用它的 `name` 与 `name` 的 PYI 首字母串作为探针。
- **样板阶段先不动**：`engineering/起步.mjs` 放的示例卡片「永磁电机」位于 `t5`，其拼音首字母串正好是 `ycdj`、字面又含「永磁」，所以开箱即全绿；等你替换成自己的内容时再改。

### 3. 引擎里的 PYI 拼音表只覆盖源内容用字

`templates/词条图鉴模板-v5.html` 的 `var PYI = {...}`（v1.1.3 时在第 **2699** 行；**行号会随母版增行而漂移，搜 `var PYI` 最稳**）——源内容实际用到的 **1490** 个汉字 → 拼音首字母。新主题会缺字，`engineering/校验.mjs:240-257` 会点名缺哪些（形如 `id·名称「某」`）。按提示把「汉字 → 拼音首字母」补进母版这张表，重跑拼合即可。PYI 只影响拼音搜索，缺字不会让站点崩。

## 二、第一次跑会遇到的红字

模板刻意不带内容数据，所以「clone 下来直接构建」必然报错——这是预期状态，不是仓库坏了。四类红字的成因与处理：

| 现象 | 成因 | 处理 |
|---|---|---|
| `拼合.mjs` 抛 `ENOENT ... dist\<产物名>.html` | 脚本不自建 `dist/`（源项目里该目录一直存在，因此当年的模板没暴露这一点） | `mkdir dist`，或跑 `node engineering/起步.mjs` |
| `拼合.mjs` 抛「`content/知识库` 下没有任何 .md 分册」 | 知识库是内容权威源，空库不构成一个站点 | 先写第一张卡片，或跑 `起步.mjs` |
| 校验报「词条清单：`content/词条清单.md` 不存在或无法解析」 | `校验.mjs:148-160` 是硬闸门：清单是内容线的唯一选题依据 | 建 `content/词条清单.md`（格式见 `content/内容规范.md` §5），或跑 `起步.mjs` |
| `#debug` 报「CHANGELOG 必须是数组」或警告「CHANGELOG 为空」 | 缺 `content/更新日志.md` 时拼合写 `CHANGELOG = null`；空文件则降级为警告，而校验要求精确的「0 错误 · 0 警告」 | 建 `content/更新日志.md` 并至少写 1 条，或跑 `起步.mjs` |

一条命令解决以上四类：`node engineering/起步.mjs`（它可反复运行，已存在的文件一律跳过）。

**第五类：不是红字，但更隐蔽——没装 Chrome 的机器上「退出码 0」不等于真检过。**

`校验.mjs:18` 写死了 `C:/Program Files/Google/Chrome/Application/chrome.exe`。Chrome 不在该路径时，`#debug` 与搜索语料回归这几项会降级为「⏸ 需外部验证」并单独计数，**退出码仍然是 0**。于是同一份代码在两台机器上会得到相反的通过口径：

- 有 Chrome（且命中该路径）：探针命中 0 卡 → 判红、退出码 1；
- 没 Chrome：跳过 → 退出码 0。

要拿到确定结论，请把该行改成你机器上的真实路径，或手动执行它打印出来的 chrome 命令，核对报告里有「0 错误 · 0 警告」。（2026-10-05 独立黑盒测试实测。）

## 四、可选：项目进度看板

`templates/项目进度模板-v1.html` 是单文件进度看板：顶部「现在在哪」三句 + 阶段进度条，下面依次是知识地图覆盖、阶段路线、所有词条、做过什么、接下来做什么、文件清单、卡点与待定。

- **用法**：拷到项目的 `docs/项目进度.html`，**只改 `var DATA = {...}` 数据区**，渲染代码一个字都不用动；双击即开，零依赖、零外部请求，也不参与构建。
- **数据区形状**：文件顶部注释 + 里面的示例数据已给全。`state` = `done` / `doing` / `todo`；`files[].k` = `ro`（只读文档）/ `do`（脚本产物）。
- **`batch` 的语义是「已交付词条清单」**，正常全是 `done`——统计磁贴的文案按这个口径写死（「全部已交付」）。未开工的内容写进 `topics` / `stages` / `next`，不要塞进 `batch`。
- **维护规则**（文件内注释也写了一遍）：只折「条目多且会持续增长」的块；**折叠 ≠ 删除**，真正的删减要先问使用者。

## 五、窄屏体检（`engineering/体检.mjs`）

只在宽屏开发、窄屏不验，就会留下「窗口一窄就坏」的缺陷。2026-10-07 修的那个顶栏语言按钮折行就是典型：只在 **561–960px 视口**出现，在真实项目里**藏了 10 天**没人发现。

```bash
node engineering/体检.mjs                    # 16 档宽度（320–1600px）× 4 个视图
node engineering/体检.mjs --quick            # 只扫 375 / 768 / 1280 三档
node engineering/体检.mjs --lang=en          # 改扫英文界面（英文标签更长，最容易折行）
node engineering/体检.mjs <某个站点.html>     # 体检任意产物（包括别的项目产出的）
```

- **体检项**：① 页面横向溢出 ② 顶栏内容溢出自身 ③ 顶栏元素越出右边界 ④ 顶栏短标签折行 ⑤ 可见文本被截断 ⑥ 顶栏文字 / 盒子的垂直对齐（偏离本行中线 > 1.5px 即报）；
- **判定**：有问题就逐条打印「宽度 / 视图 / 问题」并**退出码 1**；全清则打印「体检通过」退出码 0；
- **需要无头 Chrome**（路径常量与 `校验.mjs:18` 相同）；本进程起不了 Chrome 时记「需外部验证」并退出 0，不误判为失败；
- 它的折行判据是「**文字节点按行分组后的行数**」，所以不会被 `min-height:44px` 这类"盒子高但文字是单行"的规则误伤；反过来，「盒子被撑高、文字却顶对齐」这种**错位**由第 ⑥ 项抓——v1.1.3 修的顶栏 −5px / −9px 就是它抓出来的。

### 为什么它把页面塞进 iframe（2026-10-07 实测）

Windows 上 headless Chrome 用的是**真实窗口**，而窗口宽度有最小值（本机 500px），再扣掉 16px 窗口边框：

| `--window-size` | 320 | 375 | 480 | 560 | 768 | 1280 | 1600 |
|---|---|---|---|---|---|---|---|
| 实际 `innerWidth` | 500 | 500 | 500 | 544 | 752 | 1264 | 1584 |

于是**旧的 16 档里有 5 档（320 / 360 / 375 / 414 / 480）是重复的 500px**——最窄的那批屏幕从来没被验证过。现在体检把待检页面放进「宽度 = 目标宽度」的 `iframe` 里跑：媒体查询、`100vw`、`position:fixed` 都按 iframe 视口生效，等价于真机宽度；每档跑完还会回读一次实际 `innerWidth`，与目标不符就把「视口宽度不符」列进问题清单（英文档同理自检 `html.lang`）——**测不到就说测不到，不再假装测过**。

**同一个坑也会坑到截图**：`chrome --headless=new --window-size=375,900 --screenshot=...` 写出的 PNG 是 375×900，但页面是按 500px 排的、右边被裁掉（看着像「收藏」按钮溢出，其实是假象）；`--window-size=1280,400` 的截图同理是 1264px 版面 + 右侧 16px 空白。**要看真实窄屏，用 DevTools 的设备工具栏（Ctrl+Shift+M）或真机，别信 `--screenshot` 出的窄图。**

改样式的建议顺序：改完 → `node engineering/拼合.mjs` → `node engineering/体检.mjs`。

## 六、骨架的权威与同步纪律（2026-10-07 定）

- **本仓库是骨架的权威来源**：引擎母版与工程线脚本的改动**先在本仓库落地** → 记进 [CHANGELOG.md](../CHANGELOG.md) 的「骨架变更」→ 再分发给派生项目。
- **派生项目是消费者**：按 CHANGELOG 逐条对照同步，**只改骨架，不要覆盖自己的 `content/`**。
- **反向纪律**：如果你在自己的活动项目里改了骨架（真实内容在那边，内容驱动的引擎问题——例如 PYI 缺字——只有它跑得出来），**当天把它搬回本仓库**并记一行。
- **判据**：谁先改的那一行就是临时权威；怕的不是谁先改，是"各改各的、互不知情"。

**真实案例（为什么要有这条）**：`af88476` 之后，源项目给 PYI 拼音表补了 5 个字（糙簧魔泊毯），模板这边修了顶栏折行——两边各改一行、互不知情，结果**模板缺拼音表、源项目缺修复**，谁都不是最新。v1.1.2 就是把这两处一次性拉平。

**怎么发现已经分叉**：在两边各自的仓库里跑同一条命令，比对输出：

```bash
git hash-object templates/词条图鉴模板-v5.html
```

哈希不同就是分叉了；再看差在哪几行：`git diff --no-index <A 的母版> <B 的母版>`。经验上引擎每次分叉都只差几行，但**发现得越晚，合并时越容易漏**。
