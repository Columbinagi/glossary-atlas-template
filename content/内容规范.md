# 内容规范 · 内容线工作手册

> **这份文件给谁读**：负责撰写/修订词条的内容创作者与外部 AI。你只与 `content/` 目录打交道，不需要读引擎源码，也不需要打开站点 HTML。
> **协作分工**：内容线 = 本目录（词条与文案）；工程线 = `engineering/`（引擎 + 构建脚本）。两边只通过「数据契约」衔接。

---

## 1. 你的工位（能做什么、不能做什么）

| 动作 | 允许 |
|---|---|
| 修改 `content/知识库/<主题名>/` 下的**词条卡片**（一个术语 = 一张卡片 = 一个 md 文件，如 `content/知识库/电驱与电机/120-pmsm.md`） | ✅ 这是你唯一的写入点——**只写 Markdown** |
| 新增词条 = 新增一张卡片文件，放进所属主题的子目录（编号规则见 §5） | ✅ |
| 先写草稿放 `content/草稿/`（**不被拼合读取**，所以草稿不会污染站点），审阅通过后再收录 | ✅ 推荐：用技能 `skills/term-card-draft/SKILL.md` 生成、`skills/term-card-publish/SKILL.md` 收录 |
| 修改 `content/站点配置.js`（主题、分类、品牌、页脚） | ✅ 谨慎：它决定全站结构 |
| 打开/修改 `新能源汽车知识图鉴.html`（拼合产物） | ❌ 它是产物，改了会被下次拼合覆盖 |
| 修改 `engineering/` 下任何文件 | ❌ 那是工程线领地 |
| 新增字段名、改名、改字段语义 | ❌ 数据契约冻结（见 §2 前言） |

## 2. 改完之后（收尾流程，缺一不可）

```bash
node engineering/拼合.mjs    # ① 合入站点文件（递归扫描 content/知识库/ 下全部 md 卡片 + content/站点配置.js）
node engineering/校验.mjs    # ② 自检：0 错误才算完成
```

① 按卡内 `## N.` 编号排序把全部词条合成 `KB_TERMS`（英文卡片另合成 `KB_TERMS_EN`）；② 会逐条校验词条语法、产物内联 JS，并跑站点内置的 `#debug` 与 `#debug&lang=en` 自检（悬空引用、必填缺失、类型错误都会被抓出来），另外还查两件事：**主线编号是否重复**、**卡片「写出 → 读回」是否无损**（后者是技能生成卡片的地基）。**报告非 0 错误时，按报错信息修数据，不要绕过校验。**

## 3. 数据契约（字段冻结：只有这些名字，只有这些含义）

词条对象进入 `KB_TERMS` 数组。**除 `id` / `name` / `definition` 外全部可选**，留空则对应模块不渲染。

| 字段 | 类型 | 说明 |
|---|---|---|
| `id` | 必填 | 唯一标识，只允许小写字母/数字/连字符（hash 路由、互链、收藏都靠它） |
| `topic` | 必填（`cat` 为空时） | 所属主题 id |
| `cat` | 可选 | 所属分类 id |
| `name` / `nameEn` | 必填 / 可选 | 词条名 / 英文名（有 nameEn 会出现发音按钮） |
| `scenario` | 可选 | 「你可能会说」：使用者脱口而出的那句话 |
| `definition` | 必填 | 加粗总起句，一句话说清是什么；支持 `[[词条id|文字]]` 互链 |
| `defNote` | 可选 | ·详解：划边界、举例；同样支持互链 |
| `prereqs` | 可选 | `[{name, id}]` 先知道胶囊（id 省略 = 纯文字） |
| `aliases` | 可选 | `[字符串]` 别名 |
| `demo` | 可选 | 示意插图 HTML（Demo Kit 积木或内联 SVG）；卡片与详情共用 |
| `demoAnswer` / `demoNote` | 可选 | 图下的结论句 / 演示注解小字 |
| `demoCtl` | 可选 | `{states, init, acts:[{label, step}\|{label, to}]}` 可操作状态机 |
| `sections` | 可选 | `[{h, paras:[]}]` 正文分点 |
| `usage` | 可选 | `{do:[{text,mock}], dont:[{text,mock}]}` 什么时候用/不用 |
| `anatomy` | 可选 | `{stage, parts:[{idx,pn,pe,pd}]}` 组成结构（SVG 内 `data-ap` 与 `idx` 配对） |
| `variants` / `scenes` | 可选 | 常见变体 / 典型使用场景 |
| `confusions` | 可选 | `[{name, say}]` 容易混淆的地方 |
| `quiz` | 可选 | `{q, options:[], answer:下标, explain}` 选择题 |
| `aiPrompt` | 可选 | 「你可以这样告诉 AI」的提问模板 |
| `next` | 可选 | `[{id, note}]` 接下来学什么（**只能指向已存在的词条**） |
| `refs` | 可选 | `[{name, url}]` 延伸阅读与来源（url 写 https:// 不产生外部请求） |
| `flow` | 可选 | `{title, note, steps:[{tag,sub,mock}], current}` 路径步骤条（3–7 步，current 从 1 起） |

**语法限制**：正文强调只用「」或互链；引擎不解析 Markdown 加粗（`**x**` 会原样显示星号）。

## 4. 写作纪律（长期有效）

1. **时间锚点**：凡数据类表述必须带时间（如「截至 2026 年上半年」），并在 `refs` 标注来源；概念类表述可长期使用。查不到的写「未公开」，不用行业平均值补位。
2. **比较三件事**：凡「A 比 B 强多少」，必须同时交代**分母口径、工况（峰值/持续）、产品阶段（原型/量产）**；三项不同就声明「不可直接比较」。
3. **学理优先**：解释「为什么」，不是罗列「是什么」；不写成参数表。
4. **不写投资建议**，不预测股价与销量排名。
5. **客观中立，不预设读者身份**（2026-09-22 使用者定）：内容面向「要入门新能源汽车行业的学习者」，**不按使用者的职业岗位定制视角**。与工业电机、工业变频器等相邻领域的对照**可以有**——它本身是行业知识的一部分——但要**从简、中立、以事实陈述的方式写**，不能成为每张卡片的固定栏目，更不能出现「你们厂」「你的本行」这类指向使用者身份的措辞。
6. **信息准确性由撰写方负责**（2026-09-22 使用者定）：来源是否权威、口径是否说清、数字能否交叉验证，**都是撰写方的责任，不要指望使用者替你判断**。取源优先级：标准原文 / 官方发布 > 第三方机构 > 行业媒体；**查不到权威出处就写「未公开」**，不用行业平均值补位，不把推测写得像结论。凡引用的数字，`refs` 里要能指到具体出处与时间。

## 5. 顺序与位置（重要：卡内 `## N.` 编号 = 声明序 = 学习主线）

- **一个术语 = 一张卡片 = 一个 md 文件**：`content/知识库/<主题名>/<编号>-<id>.md`。主题名取 `content/站点配置.js` 里 `TOPICS[].name`；编号是三位数、**基础步长 5**（2026-10-02 由 10 改；容量 200 项，理由见 `词条清单.md` §一）。
- **要写哪一条，以 `content/词条清单.md` 为准**（2026-10-02 立）：那是全项目词条清单、内容线的**唯一选题依据**——清单里有的才写，想写清单外的先往清单加行。清单里同时定死了每条的编号与 id。`校验.mjs` 有清单闸门：卡片不在清单里 / 编号或名称对不上 / 清单标「已上线」却没卡片，都会报错。
- **卡内 `## N. 词条名` 的 N 就是声明序**，也就是学习主线：列表页顺序、详情页左右切换、「接下来学什么」三处都按它走。**文件名前缀必须与 N 一致**（`校验.mjs` 会检查并提示）。
- **新增词条**：
  - 追加到主线末尾 → 取「大于当前最大值的最小未占用 5 的倍数」（当前最大 620，则取 625）
  - 插入主线中间 → 取前后两张卡之间的未占用整数（如 620 与 630 之间取 625）
  - **空隙用尽时**（例如 620 与 625 之间还要插卡）→ 跑 `node engineering/重排编号.mjs --step=5`。它**保序**，只改文件名前缀与卡内编号；但它是"全站压实"，改动面大，日常新增不必跑它。
- 编号只用于排序与文件名，**站点里不显示**；互链与 `next` 一律走 `id`，所以重排编号不会打断任何引用关系。
- `next` 与 `[[互链]]` **只能指向已存在的词条**（`#debug` 会报悬空引用）；跨条引用等被引用词条落地后再补。

## 7. 英文卡片（`content/知识库-en/`，可选）

英文版站点用的译文卡片，与中文卡片**同主题子目录、同编号、同 id**（如 `content/知识库-en/电驱与电机/120-pmsm.md` 对应 `content/知识库/电驱与电机/120-pmsm.md`）。引擎按 id 合并，缺谁回退谁的中文。

- **文字节**（可写、建议写全）：你可能会说 / 是什么 / 详解 / 先知道 / 别名 / 一句话 / 演示注解 / 主线位置 / 组成结构（部件行）/ 正文分点 / 使用场景 / 容易混淆 / 选择题 / 告诉 AI / 接下来学什么 / 来源。
- **图形节（2026-09-20 起可写，按需渐进）**：`### 图解` / `### 可操作演示` / `### 组成结构`（含舞台图代码块）/ `### 使用场景` 与 `### 常见变体` 里的 mock 代码块。**写了就用英文图替换中文图；不写就继续显示中文图**——所以可以先翻文字、后补图，互不阻塞。
- **图形节的写法**：从中文卡片复制整段 HTML，**只把可见文字换成英文**（`<text>` / `<b>` / `<small>` / `<code>` / `<span>` 里的文案、`mk-*` 积木的标签），**结构与 CSS 变量原样保留**（`var(--brand)` 等是明暗主题自适应的关键，改了会掉色）。
- **格式标记沿用中文**：`## N.` 分隔标记与 `当前:` / `标题:` / `说明:` / `答案:` / `解析:` / `——` 等格式标记不翻译；`- 英文名:` 行可省略（卡片本身已是英文名）。
- **三个易踩的格式坑（2026-09-20 实测）**：
  1. **`### 来源` 的名称与 URL 之间必须是全角「：」**——写成半角 `: ` 时解析器不认，该条的 URL 会被整段丢掉（只留名称）。正确：`- Gasgoo Automotive Research Institute：https://...`
  2. **`### 先知道` 的互链必须写成「名称（见 [[词条id]]）」**——括号与「见」都是全角，且顺序固定。写成 `(see [[id]])` 时互链不生效，会原样显示成文字。
  3. **`### 组成结构` 的部件行用全角「：」分隔名称与说明**：`1. Inverter（Inverter）：converts DC into...`。半角 `:` 能解析（引擎两种都认），但**中文卡片与英文卡片统一用全角**，免得两份卡片结构看起来不一样。
  > 这三条同样适用于中文卡片（契约一致）。
- **合并规则**（引擎 `termsView()`）：中文词条为壳；文字字段 EN 给了就覆盖（name / scenario / definition / defNote / prereqs / aliases / demoAnswer / demoNote / sections / confusions / quiz / aiPrompt / next / refs）；图形字段（demo / demoCtl / anatomy.stage / usage 的 mock / variants 的 mock / scenes 的 shot / flow 的 step mock）**EN 给了才覆盖、缺则保留中文图**。
- **验收同样两步**：`node engineering/拼合.mjs` → `node engineering/校验.mjs`（校验会报告「英文分册 N 条」，并检查每条 id 是否都能在中文表命中）。

## 8. 英文翻译的开展时机与单元（2026-09-20 定；2026-09-26 使用者收窄，以本节为准）

中文是**唯一权威源**，永远先写中文。英文不是"第二条内容线"，而是从中文派生出来的工作流 —— 时机与单元按下面三条办：

1. **默认不翻、按需启动（2026-09-26 使用者定）。** 等中文版大体完成、或使用者中途明确要求时再开翻译。原因（使用者原话归纳）：中英两版同时推进，中文侧一旦出错两版都要返工——返工成本要控住。
2. **翻译单元 = 「已定稿的中文卡」。** 定稿 = 使用者审阅过、或明确确认过；没定稿的卡不要翻。英文卡是独立文件、按 `id` 与中文卡配对（不占编号位置、不依赖顺序），未译的自动回退中文。
3. **成批翻，不逐条同步翻。** 每积累 **3–5 条**定稿卡后开一轮。原因：同一个术语在不同卡片里必须译成同一个词，而「术语一致性」只有把几张卡放在一起看才发现；逐条翻最容易漂。

**翻之前先查 `content/术语对照表.md`（译名基准）。** 表里没有的术语，翻完回填进去 —— 这张表是英文侧唯一的一致性保障，也是排查「英文卡落后于中文卡」时的唯一依据。

**翻的时候只做翻译，不改内容。** 注意一个盲区：中文卡改了口径而英文没跟上时，站点上英文版会**静默显示旧内容** —— 现有校验只查英文卡 id 是否存在，**查不出内容是否同步**。所以每次改中文卡之后，顺手确认该 id 有没有对应英文卡、需不需要同步。
