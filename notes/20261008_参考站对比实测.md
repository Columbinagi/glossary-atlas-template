# 20261008 参考站对比实测（vibe-hub.org）

> **类**：分析 / 论证（**只增不改**）。触发：使用者 2026-10-08 指示「我这是有一个参考站的……好好向这个参考站学习学习」。
> 方法：用本仓库既有的 CDP 探针（`logs/morph-返回弹跳复现/probe11–17.mjs`）**把参考站量成数字**，不靠肉眼与印象。
> 结论去向：`CHANGELOG` 续 17（跨词条过渡照它改）、本文 §5（返回列表那条我们做得比它好）。

## 1. 同源证据（我们当年就是照它抄的）

在参考站详情页抓到的 CSS 规则，与我们的引擎几乎逐条一致：

| 参考站 | 我们母版 |
|---|---|
| `::view-transition-old(root){animation:none}` | 同 |
| `::view-transition-new(root){animation:.18s ease-out vt-fade-in}` | 同 |
| `::view-transition-group(morph){animation-duration:.45s; timing cubic-bezier(.22,1,.36,1)}` | 同（连组名 `morph` 都一样） |
| `html[data-dir=next]::view-transition-old(detail-body){…vt-slide-out-l…}` | 同款左右滑动（我们收到 8vw，参考站 16vw） |
| `html[data-dir=open]::view-transition-new(detail-body-enter)`（`transform-origin:50% 12%`、`.32s`、延迟 `.11s`） | 同 |
| `float-nav left/right`（`position:fixed; top:400px; transform:translateY(-23px)`）、`detail-back-button` | 同（我们 `top:50%` + `translateY(-50%)`） |

它也是**客户端路由 + 同文档 View Transition**：点击后 `location.pathname` 变了但页面没卸载（`window.__alive` 仍为 1），并在离开时调用 `document.startViewTransition`。

## 2. 关键差异：它**在开过渡之前**就把滚动归零

点「下一个条目」（从 `scrollY=900`）时，探针记到的时间线：

```
t=1931  scrollTo({top:0, behavior:'instant'})      ← 先归零
t=1935  startViewTransition(dir=next, names=detail-body)   ← 4ms 后
t=1955  scrollTo({top:0, behavior:'instant'})      ← 回调里再归零
结束：scrollY=0，path=/undo
```

于是它的 `detail-body` 组在整段过渡里 **y 恒为 149（垂直位移 0px）**、高度 1775→1948 补间 —— 只有左右滑动，没有任何斜向。

**我们原来的做法相反**：`paint()` 在过渡**回调里**（= 快照之后）才 `scrollTo(0,0)`，旧快照留在阅读位置 ⇒ 组要额外补间"你滚过的距离"（实测滚 100/200/239px → 斜向位移 100/200/239px），超过 240px 还被旧守卫直接砍掉动画。**已按参考站改**（`CHANGELOG` 续 17）。

> 顺带一条导航时延：参考站点击后有 ~1.7s 才切（它在取数/准备），期间画面不动；我们这边是同帧切换。这解释了为什么它的过渡看起来"从容"。

## 3. 它「返回列表」那一条：**和我们报过的毛病一样**

从 `scrollY=900` 的详情页点返回按钮：

```
t=111   startViewTransition(dir='', names=morph)   ← 先开过渡，此时 scrollY 仍是 900
t=197   scrollTo({top:707.9, behavior:'instant'})  ← 回调里才滚到列表的恢复位置
逐帧：morph 副本 y = −446 → 18 → 177 → 219 → 234 → 236
```

即：**morph 起点在视口上方 446px（画外），然后飞回卡片** —— 正是使用者续 14 报的那个现象。**参考站也有这个缺陷。** 我们续 14 的处理（hero 已滚出视口就不挂 morph、退化为淡入）比它更讲究，**保留不动**。

## 4. 它的语言切换：同样保不住"内容位置"

详情页滚到 1161 后切英文：

| | scrollY | 锚点（同一节）视口 top | 文档高 |
|---|---|---|---|
| 中文 | 1161 | 202 | 2168 |
| 英文 | **1357** | 89 | 2324 |

→ 参考站**scrollY 也变了**（+196），正在读的那一节同样挪了 **113px**。也就是说：**切语言时内容位置漂移是"内容重排"的固有现象**，参考站也没有解决；而我们至少把 `scrollY` **精确保持**住了（实测 1200→1200），并且早已修掉"重渲后跳回顶部"（v5 2026-09-29 那次修复，使用者当轮报的就是这个）。

## 5. 它的抽屉分类列表：同样有"点第 N 个亮第 N−1 个"

在参考站手机视口下点抽屉里的分类，**高亮同样滞后一格**（我们用同一套 scroll-spy 阈值假设复现并定位到自家代码：阈值写死 88px = 分节 `scroll-margin-top`，判等由亚像素决定；见 `CHANGELOG` 续 18）。这属于**同类实现会踩的同一个坑**，不是我们独有的。

## 6. 可复用的三条方法（写下来给后来者）

1. **别靠肉眼对齐"感觉"**：把参考站的 `scrollTo` / `startViewTransition` 调用时间线、`::view-transition-group(*)` 的逐帧 transform 都抓出来 —— 探针 11–17 可直接改 URL 复用。
2. **看它的"时机"，不只看它的"参数"**：这次的关键不是 `.45s` 或 `16vw`（那些我们早就抄了），而是**归零发生在过渡之前**这个顺序。
3. **参考站也会错**：返回列表那条它与我们同样有 bug；学它要学**能实测验证**的部分，而不是照单全收（本文 §3 §4 §5 就是三处"它也没做好"）。
