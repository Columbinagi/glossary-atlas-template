# 20261008 同类缺陷普查（「跨时刻 / 跨视图取状态」）

> **类**：盘点 / 分析（**只增不改**）。触发：使用者问「那么类似这样的问题还有没有？需不需要再做一些排查？」。
> 前情：20261008 续 14 修掉「详情页下滚后返回，卡片从画外飞回原位」（`CHANGELOG` 续 14）；本轮是对**同一类缺陷**的普查。
> 取证脚本：`logs/morph-返回弹跳复现/probe6.mjs`（①③）、`probe7.mjs`（②⑤）、`probe8.mjs`（③④）、`probe9.mjs`（②）。全部跑在母版、1280×800、Chrome 154。

## 一、这一类到底是什么

续 14 那个缺陷可以抽象成一句话：**取了一个"当时"的几何量，等到"后来"才用，而中间状态已经变了**（morph 起点取的是 hero 此刻的视口方框，用的时候视图已经滚走了）。

顺着这个思路，引擎里同一类的还有两种变体：

| 变体 | 说明 |
|---|---|
| **A 跨时刻取几何** | 位置 / 尺寸在 T1 量、T2 用（动画、滚动恢复、锚点） |
| **B 跨视图取状态** | 页面级视图的状态在 T1 置位、T2 未清（`state.changelog` / `practice` / `compare`、模态、浮层、滚动锁） |

判定口径：**起点/来源必须可信**——不可信时要么退化为最保守的呈现（淡入 / 直切），要么把来源**记下来**而不是当场推导。

## 二、逐条结果

### F1 · 详情 → 上/下一条（`across`）在 1–240px 区间斜向漂移 ✗（同一根因的残留）

`across` 分支把 `.detail-body` 挂成 morph 名，而 `paint()` 会把新词条滚回顶部 —— 于是旧副本的 y 是"你滚到的位置"，新副本的 y 是 231。实测：

| 详情页下滚 | 过渡 | morph 副本 y | 垂直位移 |
|---|---|---|---|
| 0px | 有 | 231 → 231 | **0px** |
| 100px | 有 | 131 → 231 | **100px** |
| 200px | 有 | 31 → 231 | **200px** |
| 239px | 有 | −8 → 231 | **239px** |
| 241px | **无（vtSkip 直切）** | — | — |
| 600px | **无（vtSkip 直切）** | — | — |

即：**垂直位移恒等于滚动深度**；现有守卫是「`scrollY > 240` 就不播滑动」这个**魔数**，240px 以内的斜向原样留着 —— 而"读一点就翻下一条"正好落在这个区间。这是 2026-09-20 报障「斜向过渡」的残留，不是新问题。

### F2 · 从更新日志点进词条：页面级状态残留，切语言会把详情**带走** ✗

根因：`parseHash()` 对 `#term=…` 是**提前 return** 的，而 `state.changelog / practice / compare` 的重置写在 return **之后** → 从页面级视图进详情时这三个状态残留为 `true`。

实测（`probe9`）：

| 场景 | hash | `body.is-changelog` | 侧栏宽 | 结果 |
|---|---|---|---|---|
| 从列表进详情 | `#term=doc-online` | false | 208px | 正常 |
| 从更新日志进详情 | `#term=git-commit` | **true** | **0px** | ⚠ 同一个详情页两套 chrome（侧栏消失、主区居中） |

更严重的是第二段：在这个详情页**切语言**（菜单路径）→ `updateHash()` → `hashOf()` 里 `state.changelog` 的优先级**高于** `state.term` → 落到 `#changelog&lang=en`，**正在读的词条详情直接消失、跳回更新日志页**：

```
切语言之后：{"hash":"#changelog&lang=en","detailVisible":false,"listVisible":true}
```

附带说明：`PROBE8-B`「更新日志 → 点词条 → 按「← 返回」」看起来"回到了来源"，其实是这个残留的**副作用**（`hashOf` 因 `state.changelog` 仍为 true 才产出 `#changelog`），不是设计。
`practice` / `compare` 走的是同一条提前 return，机制相同（未逐条实测）。

### F3 · 页面内「← 返回」不记来源视图 ✗

`data-back` 一律 `state.term = null; updateHash()`，目标由 `hashOf()` **推导**（按当前 state），而不是"从哪来回哪去"：

| 场景 | 进入时 | 点「← 返回」后 | 判定 |
|---|---|---|---|
| 收藏视图 → 开卡片 | `#topic=fav` | **`#topic=t1`** | ✗ 收藏视图丢了 |
| 更新日志 → 点词条 | `#changelog` | `#changelog` | ✓（F2 的副作用，非设计） |
| 搜索结果 → 开卡片 | `#topic=t5&q=…` | `#topic=t1&q=…` | △ 搜索词保住，但**主题被改写成词条所属主题**（t5→t1） |
| 收藏视图 + **浏览器后退键** | `#topic=fav` | `#topic=fav` | ✓ |

规律同续 14：**页面内那条路径靠推导，浏览器后退那条靠历史** —— 后者总是对的。

### F4 · 放大示意图（全屏模态 ＋ 滚动锁）跨导航残留 ✗

实测（`probe7`）：

| 时刻 | `#zoomMask.hidden` | `body.style.overflow` | 滚轮 500 后 scrollY |
|---|---|---|---|
| 放大态 | false | `hidden` | 0 → 0（**锁住，符合预期**） |
| 按浏览器后退之后 | **false（模态还开着）** | **`hidden`（锁没解）** | 0 → 0（**页面被锁死，用户滚不动**） |

后退后视图已经切到列表（`listVisible:true`、hash 变空），但旧词条的全屏示意图还盖在上面，并且**用户滚动被锁**。`Esc` 与 `×` 仍能恢复（`closeZoom` 在这两条路径上），所以是"可恢复但明显不对劲"。

`closeZoom()` 的调用点只有三处：Esc 链、`#zoomClose` 按钮、点遮罩 —— **没有任何一处挂在 hash 变化 / 视图切换上**。

### F5 · 语言 / 主题色浮层跨导航残留 △（轻微）

浮层开着时按后退：`langOpen: true` 依旧。内容本身仍有效（就是语言选项），点外部即关 —— 记为轻微，与 F4 同机制。

### F6 · 语言切换恢复的是"滚动量"而不是"内容位置" ✗（轻微）

菜单路径切语言时 `preserveScroll` 存的是 `scrollY`，重排后再 `scrollTo` 回去。实测：

| | scrollY | 锚点（`.detail-section` 第 5 节）视口 top | 文档高 |
|---|---|---|---|
| 中文 | 1200 | 102 | 3549 |
| 英文 | 1200 | **231** | 3843 |

→ scrollY 保住了，但**你正在读的那一节在视口里挪了 129px**（英文重排使文档高了约 300px）。同属"恢复的量与被重排的布局不同源"。

### F7 · 「继续上次」横幅的 55px 落点差（上轮已报备，留证）

返回列表时横幅首次出现（实测高 55px），而滚动是按 `scrollY` 恢复的 → 卡片落点比点开时低 55px（238.7 → 293.7）。一次性，不是动画。

### 核查过、**没有**同类问题的路径 ✓

| 路径 | 为什么安全 |
|---|---|
| 打开卡片（列表 → 详情）的 morph | 起点是**被点的那张卡片**，必然在视口内（实测 239 → 231） |
| 浏览器后退进入详情 / 列表 | 浏览器先把滚动恢复到目标历史条目，快照在那之后才拍（实测无斜移） |
| 回到顶部 / 页内目录 / 分类目录的 `scrollIntoView` | 即时消费，不跨渲染 |
| 滚动驱动的 scroll-spy、目录右缘渐隐、浮标贴边 | 每次滚动即时量；`resize` 也重算 |
| 视图过渡名（`view-transition-name`）的挂 / 卸 | 两道兜底计时器 ＋ 代际号，实测无残留 |
| 减少动态效果（`prefers-reduced-motion`） | 直接走无过渡路径 |
| 点分类目录 / 深滚跨词条 | `vtSkip` 直切（规避了 F1 那种斜移） |

## 三、建议与优先级

| 优先级 | 项 | 理由 | 成本 |
|---|---|---|---|
| **P1** | F2 页面级状态残留 | 真 bug、可复现、**影响正常操作**（切语言把详情带走；详情页 chrome 不一致）；修法是把三个状态的重置提到 `#term=` 匹配之前（或让 `hashOf` 以 `state.term` 为先） | 小（几行）＋ 可配闸门 |
| **P1** | F4 放大态跨导航残留 | 真 bug、可复现、**页面被锁死**（虽然有 Esc 逃生）；修法是把 `closeZoom()` 挂到视图切换上 | 小（1 行）＋ 可配闸门 |
| **P2** | F1 `across` 斜向残留 | 同一根因残留；但收紧到"只要滚过就不播滑动"会牺牲"读一点就翻下一条"的横向翻页感 → **需拍板取舍** | 小（改判据）＋ 可配闸门 |
| **P3** | F3 返回目标不记来源 | 语义改进（"从哪来回哪去"）；改动面比看起来大（要么记来源 hash，要么复用 history） | 中 |
| **P3** | F5 / F6 | 轻微；F6 若要做，把锚点元素位置也一并记下即可 | 小 |

## 四、本轮的覆盖边界（**没测的部分，别当成已查**）

- **窄屏 / 触屏未覆盖**：本轮所有读数都在 **1280×800、鼠标**下取的；320–960 布局不同（顶栏重排、底栏 tab、浮标变静态），F1–F6 的行为**未验证**。这是本轮最大的盲区，也是唯一建议补做的排查（现成探针可直接复用，成本低）。
- 未跑 `any-pointer: coarse`（触屏）代码路径、未跑 Safari / Firefox（项目非目标，只做特性门槛判断）。
- 未做慢速设备 / 长任务下的时序压力测试（VT 的 250ms / 1200ms 兜底边界）。
- F2 的 `practice` / `compare` 两个入口未逐条实测（与 changelog 同一代码路径）。
