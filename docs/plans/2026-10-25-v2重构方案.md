## 3. 「单文件 + 零外部请求」能不能承载参考站的设计？

**结论：能。** 参考站的设计可以拆成「几何 / 层级 / 节奏」与「工程形态」两层：

| 层 | 能否搬 | 说明 |
|---|---|---|
| 设计 token（色、圆角、阴影、缓动、字号） | ✅ 全搬 | 纯 CSS 变量 |
| 布局（侧栏 156 / 卡片 3-2-1 / 详情居中 916） | ✅ 全搬 | Grid + `max-width` |
| 浮标三级退化 | ✅ 全搬 | 纯 CSS 媒体查询，**不需要 JS** |
| 顶栏 60→108 双行 | ✅ 全搬 | Grid 两行 |
| View Transition 时序与时长 | ✅ 全搬 | 原生 API（v5 已在用） |
| 图标（参考站用 Tabler 图标字体） | ⚠️ 替代 | 内联 SVG path；不引字体 |
| 拉丁字体 Manrope（woff2 外链） | ⚠️ 替代 | 系统栈；若要一致需内嵌子集（**+30–60 KB**，可选，不推荐） |
| 卡片位图预览（logo、示意图 PNG） | ⚠️ 替代 | 内联 SVG / 纯排版；**不搬图片资产**（版权 + 体积） |
| Next.js 流式 SSR / 增量 chunk | ❌ 不可搬 | 与「单文件」冲突，也不必要 |
| GTM / 交流群 / 社交 | ❌ 不搬 | 外链与隐私 |

**必须放宽的点：0 条。** 只有三处**视觉取舍**（字体、预览图、图标），且都落在「不引外链」一侧。若使用者要求「连字体的笔画宽度都一致」，才需要单独立项讨论内嵌 Manrope 子集，代价是产物 +30–60 KB 且要处理字体许可。

## 4. 采用 / 拒绝清单

### 4.1 采用（含理由）

| # | 项 | 理由 |
|---|---|---|
| A1 | 详情页**去掉常驻侧栏**，正文居中 916 | 直接消灭浮标遮挡的结构前提；阅读专注度更高 |
| A2 | 浮标**纯 CSS `50%` 锚定** + 56px 间距 | 不依赖 DOM 测量，窗口缩放 / 字体加载都不会错位 |
| A3 | 浮标三级退化 **1440 / 1240 / 1140** | 文本 → 仅箭头 → 静态行，阈值由列宽反算 |
| A4 | 顶栏 **60 → 1023 两行 108**，无抽屉 / 无底栏 | 参考站实测；手机上导航始终可见，少一次点击 |
| A5 | 目录侧栏 **156px**，≤1100 收窄 140/20 | 侧栏更轻，正文更宽；卡片列数稳定 |
| A6 | 卡片 **3 / 2 / 1 固定列**，gap 20 | 比 `auto-fill` 更可控，避免 300–380 区间的「半列」 |
| A7 | 字号 **31 / 30 / 28 / 20 / 15** | 参考站层级对比 2.07 倍；v5 只有 1.87 且区块题过小 |
| A8 | 圆角 **8 + 12**、双层柔和阴影、`cubic-bezier(.2,.8,.2,1)` | 观感差距的主要来源，成本极低 |
| A9 | 深色底 **`#1b1d21` / `#22252a`** | 比 v5 的近黑更有层次，且不刺眼 |
| A10 | 动效**时序收敛为 token**（`.18/.45/.32+.11/16vw`） | 现有实现已同源，只需参数化，便于体检与回归 |
| A11 | 顶栏 / 详情二级 sticky | 参考站形态；v5 已有，保留 |
| A12 | 目录页背景的极淡网格 + 径向光晕 | 纯 CSS `background-image`，零请求；提升「成品感」 |

### 4.2 拒绝（含理由）

| # | 项 | 理由 |
|---|---|---|
| R1 | Next.js / 多文件 CSS / 外部字体 / 图标字体 | 与 C1「单文件、零外部请求」直接冲突 |
| R2 | GTM、交流群弹窗、社交分享 | 外链、隐私、需要后端 |

### 5.3 布局模型

**目录页（≥1101）**

```
┌────────────────────────────────────────────── shell 1640 / padding 32 ┐
│ nav 60                                                               │
├──────────┬───────────────────────────────────────────────────────────┤
```

**目录页（≤900）**：侧栏变为**横向滚动 chip 条**，网格 2 列（≤900）/ 1 列（≤560）；不设抽屉。

**详情页（≥1241）**

```
┌──────────────────────────────────────────────────────────────┐
│ nav 60                                                        │
├──────────────────────────────────────────────────────────────┤
│ ← 返回 · 面包屑 ······················ 收藏 · 复制 Markdown   │  topbar sticky
│                                                              │
│                    H1 30 + 英文名 15                          │  ┌ 916 居中 ┐
│                    引语块（品牌淡底 + 左竖线）                 │  ◀ 54px 浮标
│                    H2 24 / 正文 15/1.7                        │     间距 56
│                    …                                          │
└──────────────────────────────────────────────────────────────┘
```

**浮标定位（v2 核心公式，纯 CSS）**

```css
.float-nav.left  { right: calc(50% + var(--detail-col) / 2 + var(--float-gap)); left: auto; }
.float-nav.right { left:  calc(50% + var(--detail-col) / 2 + var(--float-gap)); right: auto; }
```

`--detail-col: 916px`、`--float-gap: 56px` ⇒ `514px`，与参考站同值，但**变量化**。
详情页**没有侧栏**，所以「浮标压侧栏」这个 bug 在结构上不成立。

### 5.4 断点（由「列宽 + 间距」反算，不拍脑袋）

| 断点 | 依据 | 变化 |
|---|---|---|
| **1440** | 文本浮标需 `(vw − 916)/2 ≥ 140 + 56 + 12` ⇒ vw ≥ 1384 | `.fn-text` 隐藏，浮标变 54 圆钮 |
| **1240** | 圆钮需 `(vw − 916)/2 ≥ 54 + 56 + 12` ⇒ vw ≥ 1164 | 浮标贴视口 `12px`，不再跟正文列 |
| **1140** | 两枚文本按钮并排的最小宽度 | 浮标落回 `.entry-nav` 静态行 |
| **1100** | `140 + 20 + 3×280 = 1000`，再留内边距 | 目录侧栏 156→140，gap 28→20，padding 32→24 |
| **1023** | 顶栏两行放得下 logo + 搜索 + 3 个工具 + 导航 | 顶栏 60→108 双行；无抽屉 |
| **900** | `140 + 20 + 2×300 = 760`，再留内边距 | 目录侧栏变横向 chip 条；网格 2 列 |
| **560** | 详情 topbar 三项放不下 | 面包屑只留当前项；H1 26；动作图标化 |
| **480 / 390 / 320** | `体检.mjs` 既有档位 | 不新增特殊排版，只保证不溢出 |

> 断点全部落在 `体检.mjs` 的 16 档（320 / 360 / 375 / 414 / 480 / 560 / 600 / 700 / 768 / 860 / 900 / 960 / 1024 / 1200 / 1440 / 1600）可验证的位置或相邻位置；1200 与 1240 的差异会在 1200 / 1440 两档体现。

### 5.5 动效

| token | 值 | 用途 |
|---|---|---|
| `--vt-fade` | `.18s ease-out` | 根快照淡入 |
| `--vt-morph` | `.45s cubic-bezier(.22,1,.36,1)` | 卡片 ↔ 标题共享元素 |

| `--vt-enter` | `.32s`，延迟 `.11s`，`transform-origin: 50% 12%` | 详情进入 |
| `--hover` | `.22s var(--ease)` | 边框 / 阴影 / 箭头位移 3px |

**硬规则（沿用 `PRD.md` §6.1 判定口径）**：跨词条切换必须**先 `scrollTo(0)` 再 `startViewTransition`**；返回列表时 hero 已滚出视口就**不挂 morph**，退化为淡入；`prefers-reduced-motion: reduce` 时全部关闭。

### 5.6 无障碍

| 项 | 规格 |
|---|---|
| 跳转主内容 | `.skip-link` 是文档第一个可聚焦元素，指向 `#mainArea`，目标带 `tabindex="-1"` |
| 焦点环 | 统一 `outline: 2px solid var(--brand); outline-offset: 2px`，覆盖所有可见可聚焦控件 |
| 键盘 | 浮层 `Esc` 关闭并归还焦点；`?` 呼出快捷键面板；上下条可 Tab 到达 |
| 触屏 | `@media (any-pointer: coarse)` 下可点高度 ≥44px |
| 语义 | `nav` / `main` / `aside` 齐全；`aria-current` / `aria-expanded` / `aria-haspopup` 随状态更新 |
| 对比度 | 正文 ≥4.5:1；`--text-3` 用 v5 值；大字号标题 ≥3:1 |
| 动效 | 尊重 `prefers-reduced-motion` |

## 6. 回归案例：详情页浮标遮挡（根因 + 候选修法）

### 6.1 根因（证据见取证 §5）

`overlap = 浮标宽 − 14`。侧栏与正文列之间只有 28px 空档，而浮标右缘固定在「正文列左缘 −14px」，宽度又随**邻居词条名**在 41–170 之间变化：

| 浮标宽 | 41（仅箭头） | 107（5 字） | 133（6 字） | 170（触顶） |
|---|---|---|---|---|
| 重叠 | 27 | 93 | 119 | **156**（侧栏 208 的 75%） |

**这不是像素 bug，是定位模型 bug**：把「浮动元素」锚在「会变的正文列边缘」，又给它一个「会变的宽度」。

### 6.2 候选修法

| 方案 | 做法 | 代价 | 适用 |
|---|---|---|---|
| **A. 结构重建（v2 推荐）** | 详情页去侧栏、正文居中；浮标 `calc(50% ± (916/2 + 56))`；1440 / 1240 / 1140 三级退化 | 详情页不再常驻侧栏（产品变化）；窄屏浮标改静态行 | **v2** |
| **B. 夹紧式（v5 最小补丁）** | 保留 `syncFloatAnchor()`，改为量「侧栏右缘 → 正文左缘」的 `gutter`，写入 `--fl-gap`；`--fl-right = vw − body.left + gutter/2`，`max-width = max(41px, gutter − 28px)` | 仍依赖 JS 测量；`resize` / 字体加载后要重算；名字更早省略（约 0 字）；只治标 | 若先发 **v1.1.6** |
| **C. 贴视口边缘** | `left:12px / right:12px` 固定 | 1600 时浮标离正文 340px，视觉关联弱；超宽屏更远 | v2 若坚持保留侧栏 |
| **D. 放进正文流** | 静态放在顶部 / 底部 | 失去「长文随时可翻」的可达性 | 备选 |

**推荐**：v2 用 **A**；若使用者决定先发 v1.1.6，则 v1.1.6 用 **B**（一次性补丁，跑全套闸门），再进 v2。

### 6.3 方案 A 的验收断言（新增闸门建议）

在 `校验.mjs` 增一条 ③-n（或复用体检）：在 1600 / 1440 / 1320 / 1200 四档下断言
`float.left.right <= detailBody.left − 56 + 1` 且 `float.width ∈ {54, ≤176}`，
并断言静态档（≤1140）`position === 'static'`。**红绿双向**：拿 v5 母版必须判红（预期重叠 119/156）。
