# 收录并构建

输入：**人已明确说通过**的草稿文件（`content/草稿/*.md`）。
输出：卡片进入 `content/知识库/<主题名>/<编号>-<id>.md`，站点重建，校验 0 错误。

## 前置闸门（人在回路，不许自行越过）

- 只有用户明确表示「通过 / 可以收录 / 上线」才动手。用户说「帮我看看这张卡」时，**只审阅、不收录**。
- 审阅意见由**用户**给（他是本行专业者）；你只负责把意见落成修改，不要把「我检查过格式没问题」当成内容通过。

## 步骤

```bash
# ① 收录（自动分配编号 = 现有最大编号 + 5；并重建站点）
node engineering/收录草稿.mjs content/草稿/<id>.md

# ② 校验：0 错误才算完成
node engineering/校验.mjs
```

- **要插到主线中间**：先看 `--dry` 打印的位置，再用 `--num=NNN` 指定前后两张卡的中间值
  （例：想插在 160 与 165 之间 → `--num=163`；空隙用尽时先跑 `node engineering/重排编号.mjs` 恢复步长 5）。
- **英文译文卡**：`--en`，且必须已有同 id 的中文卡（编号自动镜像中文卡）。
- **先预演**：拿不准就先加 `--dry`，它只解析、只打印收录位置，不动任何文件。

## 收录后要报告什么

1. 新文件路径（`content/知识库/<主题>/<编号>-<id>.md`）。
2. 编号，以及它**排在谁的后面、谁的前面**（脚本会打印，照抄即可）。
3. `node engineering/校验.mjs` 的结果 —— 必须看到「=== 校验全部通过 ===」，且两条 `#debug` 都是 **0 错误 · 0 警告**（有警告也算没过，回去修卡片）。
4. 若用户还要英文版：提醒他英文卡是另一张草稿（`--en`），不要在这里顺手机翻。

## 校验不通过怎么办

按报错修**数据**，不要绕过校验、不要改脚本。常见几类：

- `id 与已收录词条撞车` / `该 id 的英文卡已存在` → 改草稿的 id（或确认要覆盖哪一张）。
- `悬空引用`（`#debug` 报）→ 卡里的 `[[id]]` 或 `next` 指向了还不存在的词条：要么等那张卡落地，要么改成已存在的 id。
- `往返无损` 报差异 → 卡片格式被写坏了（多半是节标题、契约标记或全角标点的问题），回草稿区按 `content/内容规范.md` 修好再收录。

## 想撤回怎么办

卡片文件用 `git` 可完整还原；也可以把卡片从 `content/知识库/` 移回 `content/草稿/`，然后重跑
`node engineering/拼合.mjs ; node engineering/校验.mjs`。**不要**用命令行 `rm` / `git rm`（本项目删除一律走 node fs API，历史上有目录级连带误删前科）。

## 不要做

- 不要在用户没确认通过时收录；不要顺手改卡片正文（那是 `term-card-draft` 的活）。
- 不要改 `engineering/` 下的脚本或 `新能源汽车知识图鉴.html`（产物会被下次拼合覆盖）。
